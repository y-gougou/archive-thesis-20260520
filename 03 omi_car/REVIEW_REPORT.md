# WHEELTEC 全向轮小车项目代码审查报告

## 审查概述

本报告由5个并行的代码审查代理生成，分别从以下维度对项目进行了全面审查：

1. **代码质量与一致性**
2. **FreeRTOS并发性**
3. **硬件驱动实现**
4. **控制算法**
5. **安全性与错误处理**

---

## 1. 代码质量与一致性审查

### 1.1 代码风格问题

| 问题类型 | 严重程度 | 描述 |
|---------|---------|------|
| 缩进混乱 | 中 | Tab和空格混用，与`.clang-format`配置不符 |
| 大括号风格 | 中 | K&R、Allman等多种风格混用 |
| 运算符间距 | 中 | `=`、`-`等运算符前后空格不一致 |
| 编码标准混用 | 中 | 同一文件中存在"新"、"旧"两种编码风格 |

### 1.2 命名规范问题

| 问题类型 | 严重程度 | 示例 |
|---------|---------|------|
| 函数命名不一致 | 中 | `Balance_task`(PascalCase) vs `systemInit`(camelCase) vs `hub_485_velocity_init`(snake_case) |
| 变量命名不一致 | 中 | 全局变量`A=1,B=1,C=1,DD=1`无描述性 |
| 宏命名不一致 | 中 | `PI`、`ZHONGZHI`、`DIFFERENCE`等无前缀 |
| 类型名不一致 | 低 | 混用`u8`/`uint8_t`、`u16`/`uint16_t` |
| 变量名拼写错误 | 低 | `Omni_turn_radiaus`应为`radius` |

### 1.3 注释质量问题

| 问题类型 | 严重程度 | 描述 |
|---------|---------|------|
| 编码损坏 | 高 | 80%以上的中文注因编码问题显示为乱码 |
| 复制粘贴错误 | 中 | MPU6050.c中多个函数注释与实际功能不符 |
| 注释掉的代码 | 低 | 项目中存在大量注释掉的死代码 |
| 函数文档缺失 | 中 | 复杂函数如`auto_pwm_clear()`无文档说明 |

### 1.4 头文件组织问题

| 问题类型 | 严重程度 | 描述 |
|---------|---------|------|
| Include Guard命名 | 中 | 使用双下划线前缀`__SYSTEM_H`（C标准保留） |
| 重复包含 | 中 | `system.h`中`usart.h`被包含两次 |
| 冗余包含 | 低 | 几乎所有头文件都包含`system.h` |
| 文件扩展名不一致 | 低 | `LED.C`、`LED.H`使用大写扩展名 |

### 1.5 魔法数字问题

| 位置 | 严重程度 | 描述 |
|------|---------|------|
| `balance.c:404-405` | 高 | PWM限制值16800无命名常量 |
| `balance.c:612-614` | 高 | PS2摇杆中心值128无命名常量 |
| `encoder.c:51` | 高 | 编码器缩放因子25无文档说明 |
| `control.c:13-16` | 高 | 单字母宏`a_PARAMETER`、`T`、`L`、`K`无上下文 |
| `can.c:333` | 中 | CAN ID `0x12345678`、`0x181`、`0x182`为魔法数字 |

### 1.6 代码重复问题

| 重复代码 | 严重程度 | 描述 |
|---------|---------|------|
| PI控制器 | 高 | `Incremental_PI_A/B/C/D`四个函数几乎完全相同 |
| 编码器初始化 | 高 | `Encoder_Init_TIM2/3/4/5`四个函数几乎完全相同 |
| HUB驱动命令 | 高 | 左/右电机命令函数大量重复 |
| 绝对值函数 | 中 | `myabs()`、`float_abs()`、`int_abs()`重复定义 |
| 卡尔曼滤波器 | 中 | `Kalman_Filter()`和`Yaw_Kalman_Filter()`重复实现 |

## 2. FreeRTOS并发性审查

### 2.1 任务优先级和栈大小

| 任务 | 优先级 | 栈大小(words) | 问题 |
|------|--------|---------------|------|
| `Balance_task` | 4 | 512 | 与`pstwo_task`、`data_task`同优先级，可能被抢占 |
| `MPU6050_task` | 3 | 256 | 栈大小适中 |
| `show_task` | 3 | 512 | 栈大小适中 |
| `led_task` | 3 | 128 | **低于FreeRTOS最小栈要求(130 words)** |
| `pstwo_task` | 4 | 256 | 位带SPI可能被调度器中断 |
| `data_task` | 4 | 512 | 忙等待浪费CPU时间 |

**建议：**
- 将`Balance_task`提升到优先级6
- 将`data_task`降低到优先级2
- 将`led_task`栈大小增加到256 words

### 2.2 临界区使用

**问题：** 除`main.c`中的启动任务外，整个应用程序代码中**没有使用任何临界区保护**。

**影响：** ISR和任务之间共享的全局变量（如`Move_X`、`Move_Y`、`Move_Z`）存在竞态条件。

### 2.3 同步原语使用

**问题：** 尽管`FreeRTOSConfig.h`启用了互斥锁、信号量等功能，但**项目中未使用任何同步原语**。

### 2.4 竞态条件

| 共享资源 | 写入者 | 读取者 | 严重程度 |
|---------|--------|--------|---------|
| `Move_X/Y/Z` (float) | 4个ISR | `Balance_task` | **高** |
| `gyro[3]/accel[3]` | `MPU6050_task` | `Balance_task`、`show_task` | **高** |
| `MOTOR_A/B/C/D` | `Balance_task` | `data_task`、`show_task` | **高** |
| 模式标志位 | ISR | `Balance_task` | 中 |
| `Voltage` | `show_task` | `Balance_task` | 中 |

### 2.5 栈溢出检测

**问题：** `configCHECK_FOR_STACK_OVERFLOW`设置为0，禁用了栈溢出检测。

## 3. 硬件驱动实现审查

### 3.1 GPIO配置

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| I2C SDA配置 | 中 | 配置为推挽输出而非开漏输出，违反I2C规范 |
| GPIO速度注释错误 | 低 | 注释说50MHz但代码设置为2MHz |
| 输出引脚上拉 | 低 | 电机方向引脚不必要地启用了上拉 |

### 3.2 定时器/PWM配置

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| TIM1重复初始化 | 中 | `Servo_PWM_Init()`和`TIM1_Cap_Init()`都初始化TIM1 |
| 时钟分频值错误 | 中 | 使用原始值`1`而非符号常量`TIM_CKD_DIV1` |

### 3.3 编码器读取

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| **读取-复位竞态条件** | **严重** | `Read_Encoder()`先读后清零，可能丢失计数 |
| 空ISR | 低 | 编码器溢出中断处理函数为空 |

### 3.4 I2C通信

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| 未初始化返回值 | **严重** | `MPU_Get_Gyroscope()`返回未初始化的`res`变量 |
| ACK检查忽略 | 中 | `I2C_WriteOneByte()`忽略ACK失败，总是返回成功 |
| 单字节读取 | 低 | 应使用突发读取减少I2C事务数量 |

### 3.5 UART/CAN通信

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| **CAN状态检查运算符优先级错误** | **严重** | `CAN1_Tx_Staus()`中`(1<<8)>>8`计算错误 |
| **花括号缺失** | **严重** | `HubDriverCan.c`中多处`if`语句缺少花括号 |
| USART3资源冲突 | 高 | Modbus驱动和ROS数据发送共用USART3 |
| 中断处理函数返回类型 | 低 | 声明为`int`而非`void` |

### 3.6 ADC电压测量

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| 魔法数字 | 中 | 电压公式中`3.24`、`11.0`等无命名常量 |
| 阻塞轮询 | 低 | `Get_Adc()`忙等待转换完成 |

## 4. 控制算法审查

### 4.1 PID控制器实现

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| **角度PID死区重置状态** | **高** | 死区内重置`Integral`和`Last_Bias`，导致退出时产生微分冲击 |
| **无角度 wrapping** | **高** | 角度误差在0/360度边界计算错误，可能产生340度误差 |
| 无微分滤波 | 中 | 微分项直接使用差分，放大传感器噪声 |
| 静态局部变量 | 中 | PI控制器使用静态变量，无法支持多轴控制 |

### 4.2 运动学计算

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| 全向轮运动学 | 无 | 3轮全向轮运动学计算正确 |
| 麦克纳姆轮运动学 | 无 | 4轮麦克纳姆轮运动学计算正确 |
| 两轮运动学 | 低 | `tan(angle)`在90度时会发散，但输入范围有限 |

### 4.3 速度平滑

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| 固定步长 | 中 | 步长0.02 m/s导致全范围速度变化需要1.75秒 |
| 死区阈值 | 低 | 死区阈值0.05大于步长0.02，导致停止行为不均匀 |

### 4.4 卡尔曼滤波器

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| **偏航卡尔曼滤波器编码器测量禁用** | **高** | `Yaw_Angle_err = 0`导致偏航角仅靠陀螺仪积分，会漂移 |
| 全局变量 | 中 | 所有滤波器状态为全局变量，存在竞态条件 |

### 4.5 PWM限制

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| `Limit_Pwm()`未调用 | 低 | 定义了PWM限制函数但从未调用 |
| 静态幅值变量 | 低 | `Drive_Motor`中的幅值为静态变量，无法运行时修改 |

## 5. 安全性与错误处理审查

### 5.1 电压监控和低电池保护

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| **低电压阈值错误** | **严重** | `voltage < 20`阈值实际上禁用了低电池保护 |
| PWM通道不完整 | 高 | `Turn_Off()`只清零2个PWM通道，C和D通道未清零 |
| 无滞回 | 中 | 电压恢复后立即重新启用电机，可能导致振荡 |

### 5.2 电机故障检测

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| **无运行时故障检测** | **严重** | 自检仅在启动时运行，运行中电机断开无法检测 |
| 无过流保护 | 高 | 无电流传感硬件，堵转电机无限期输出最大电流 |
| 无编码器可信度检查 | 高 | 编码器故障时PI控制器会饱和 |

### 5.3 看门狗使用

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| **无硬件看门狗** | **严重** | 程序挂起时电机会无限期保持最后命令 |
| 故障处理函数 | 高 | `HardFault_Handler`等只进入死循环，不禁用电机 |
| 栈溢出检测禁用 | 中 | `configCHECK_FOR_STACK_OVERFLOW = 0` |
| 内存分配失败钩子禁用 | 中 | `configUSE_MALLOC_FAILED_HOOK = 0` |

### 5.4 急停机制

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| **通信超时注释掉** | **严重** | `command_lost_count`逻辑被注释，通信中断后车辆继续执行最后命令 |
| 无专用急停输入 | 高 | 无物理急停按钮、碰撞开关或倾斜传感器 |
| 倾斜检测缺失 | 中 | 无跌倒保护机制 |

### 5.5 自检功能

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| 启动时移动电机 | 中 | 自检时物理移动电机，在架子上或边缘附近有危险 |
| 无法跳过自检 | 中 | 无按钮或命令跳过自检 |

### 5.6 充电安全

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| **充电硬件检测代码无效** | **严重** | `CAN1_RX0_IRQHandler`中检测循环为空，永远无法检测充电底座 |
| 无充电电流限制 | 高 | 读取`Charging_Current`但从未检查是否超限 |
| 无充电超时 | 中 | 充电模式可无限期持续 |
| 平滑控制绕过 | 中 | 充电模式下速度命令无平滑处理 |

### 5.7 通信超时处理

| 问题 | 严重程度 | 描述 |
|------|---------|------|
| **超时逻辑注释掉** | **严重** | 通信中断后车辆继续执行最后命令 |
| 无心跳机制 | 高 | 无法区分"保持速度"和"通信断开" |
| `command_lost_count`类型 | 中 | `u8`类型在2.55秒后溢出 |

## 综合评估

### 严重程度统计

| 严重程度 | 数量 |
|---------|------|
| **严重(Critical)** | 12 |
| **高(High)** | 18 |
| **中(Medium)** | 25 |
| **低(Low)** | 15 |

### 关键发现摘要

#### 必须立即修复的问题

1. **无硬件看门狗** - 程序挂起时电机失控
2. **通信超时注释掉** - 通信中断后车辆继续运动
3. **低电压阈值错误** - 低电池保护形同虚设
4. **充电硬件检测代码无效** - 充电功能无法正常工作
5. **编码器读取竞态条件** - 可能丢失计数导致控制误差
6. **CAN状态检查运算符优先级错误** - 邮箱1和2状态检查错误
7. **HubDriverCan.c花括号缺失** - 加减速参数设置错误

#### 高优先级修复

1. 添加临界区保护ISR共享变量
2. 修复角度PID的angle wrapping问题
3. 禁用偏航卡尔曼滤波器的编码器测量
4. 修复角度PID死区状态重置问题
5. 增加`led_task`栈大小
6. 启用栈溢出检测
7. 故障处理函数中禁用电机

## 修复建议

### 阶段1：安全关键修复（1-2天）

1. 启用IWDG看门狗，超时500ms
2. 取消注释并修复通信超时逻辑
3. 修复低电压阈值（改为9000对应9V）
4. 修复`Turn_Off()`清零所有4个PWM通道
5. 在故障处理函数中禁用电机PWM

### 阶段2：控制算法修复（2-3天）

1. 修复角度PID的angle wrapping
2. 修复角度PID死区状态重置
3. 重新启用偏航卡尔曼滤波器编码器测量
4. 添加微分项低通滤波

### 阶段3：并发性保护（1-2天）

1. 为ISR共享变量添加临界区保护
2. 调整任务优先级
3. 启用栈溢出检测
4. 增加`led_task`栈大小

### 阶段4：驱动层修复（2-3天）

1. 修复编码器读取竞态条件
2. 修复CAN状态检查运算符优先级
3. 修复HubDriverCan.c花括号缺失
4. 修复MPU6050未初始化返回值
5. 优化I2C为突发读取

### 阶段5：代码质量改进（持续）

1. 统一编码风格，运行`.clang-format`
2. 提取魔法数字为命名常量
3. 重构重复代码
4. 修复注释编码问题
5. 补充函数文档
